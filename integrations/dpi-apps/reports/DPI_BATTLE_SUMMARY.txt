1. THE DPI EQUIPMENT & TOPOLOGY (FROM HUAWEI_THE_DPI_DEVICE & DPI_INFRASTRUCTURE)
--------------------------------------------------------------------------------
Hardware/Role:
- Carrier-grade inline DPI middlebox deployed at the MCI mobile packet core (PGW/GGSN)
  and upstream TIC international transit interfaces.
- The equipment performs stateless and stateful inspection of IPv4/IPv6 transit flows.
- Operates inline without terminating TLS; Cloudflare's genuine certificates are delivered intact.
- MTU is unaltered (1472-byte payloads pass).
- Ports: Middlebox inspects all common TLS ports (443, 8443, 2053, 2083, 2087, 2096).
- Independent of protocol payloads: VLESS, Trojan, static HTML, or binary WebSocket
  streams are treated identically if the SNI triggers the rule.

2. THE TWO FILTERING MECHANISMS IDENTIFIED
--------------------------------------------------------------------------------

[MECHANISM A: In-Path DNS Poisoning & Interception]
- Scope: UDP and TCP port 53.
- Action: Intercepts all DNS queries in transit (even when directed to public IPs like
  1.1.1.1, 8.8.8.8, 9.9.9.9) and synthesises a forged 'A' record pointing to private
  sinkhole IP: 10.10.34.36 (with a high TTL of ~418-420 seconds).
- Targets: youtube.com, instagram.com, twitter.com, pages.dev, trycloudflare.com,
  and all standard DoH resolver domains (dns.google, cloudflare-dns.com).
- 0x20 Case Randomisation in DNS: DOES NOT WORK (middlebox normalises DNS query case).
- Sinkhole Behavior: 10.10.34.34 / .35 / .36 drop 100% of packets on all ports.
- Exception: workers.dev and cloudflare.com are NOT in the DNS poison table and resolve
  to real Anycast IPs.

[MECHANISM B: Inline SNI Flow Termination]
The DPI applies different actions depending on the target domain:
A) For pages.dev (and blocked DoH domains):
   - Injects a spoofed TCP RST during the TLS handshake.
B) For workers.dev subdomains:
   - Does NOT inject TCP RST (0 RSTs in pcap).
   - Allows the full TLS 1.3 handshake to finish cleanly (ClientHello -> ServerHello ->
     Certificate -> Finished).
   - The moment the client sends its first application-layer packet (e.g. HTTP GET /
     WebSocket Upgrade), the DPI silently blackholes/discards all client application
     segments.
   - Client enters exponential RTO retransmissions (0.35s -> 0.70s -> 1.41s -> 2.81s
     -> 5.62s -> 11.2s) until timing out with 0 application bytes received.

3. THE SNI BOUNDED-LABEL MATCHING WINDOW (FROM SNI_FILTER_RULE_REPORT)
--------------------------------------------------------------------------------
A rigorous sweep altering only the SNI label count on the same Cloudflare IP
revealed the exact pattern matcher logic on MCI:

  SNI String                      Labels   DPI Verdict   Network Behavior
  ------------------------------  -------  -----------   ------------------------------
  workers.dev                         2     ALLOWED       HTTP/1.1 301 received
  a.workers.dev                       3     BLOCKED       Handshake ok -> App data dropped
  a.b.workers.dev                     4     BLOCKED       Handshake ok -> App data dropped
  a.b.c.workers.dev                   5     PASSED        Traverses filter -> CF TLS alert
  a.b.c.d.workers.dev                 6     PASSED        Traverses filter -> CF TLS alert

Key Insights:
- The classifier uses an anchored string pattern matching at most 4 dot-separated labels.
- Subdomains with 5 or more labels fall outside the pattern window and pass through.
- Case mangling (e.g. wORKErs.DEv): DEAD on MCI. The DPI normalises case.
- Length is NOT the discriminator: Names between 13 and 55 characters with 3-4 labels
  were all blocked.

4. ENCRYPTED DNS DISCOVERIES (FROM SESSION_2_FINDINGS)
--------------------------------------------------------------------------------
- DNS-over-TLS (DoT, Port 853): 100% blocked / timed out across all providers.
- DoH by Domain Name: 100% blocked via SNI TCP RST (dns.google, cloudflare-dns.com).
- DoH by IP LITERAL:
    https://8.8.8.8/dns-query  -> WORKS (Google cert has IP SAN for 8.8.8.8)
    https://8.8.4.4/dns-query  -> WORKS
  Because no domain appears in the SNI, the middlebox cannot inspect or block it.
- ISP Difference:
    MCI:     8.8.8.8 DoH works; 1.1.1.1 is filtered.
    Rightel: 1.1.1.1 DoH works; 8.8.8.8 is filtered.
  Conclusion: DoH must support dual-upstream failover (both 8.8.8.8 and 1.1.1.1).

5. METHODS TO BATTLE AND MITIGATE (ACTIONS FOR OUR PROJECT)
--------------------------------------------------------------------------------

[Action 1: Deep Hostname / Custom Domain (Solving the SNI Window)]
- Never use default *.workers.dev (sits in the 3-4 label blocked window).
- Add a Custom Domain to the Cloudflare Worker with 5+ labels:
  e.g.: a.b.c.d.yourdomain.com
- Cloudflare automatically provisions the SSL certificate and handles deep subdomains.
- Because it has 5+ labels, it passes outside the DPI's 4-label match window.

[Action 2: Clean IP Pinning (Bypassing Layer 4 SYN Drops)]
- System DNS resolves Cloudflare to IPs like 104.18.x.x, where port 443 SYNs are dropped.
- In client configurations:
  - Set 'address' (connection IP) to: 188.114.96.1 (measured: 187 ms, 0% loss on MCI)
  - Secondary fallback IP: 188.114.96.3
  - Set 'Host' / 'SNI' to your custom domain.

[Action 3: Fast-Fail Socket Timeout (Neutralising Post-Handshake Silence)]
- Because the DPI blackholes packets after the handshake rather than resetting them,
  standard clients wait 30+ seconds in exponential RTO retransmissions.
- Set client connect / first-byte timeout to 2.0 - 2.5 seconds.
- If no application bytes arrive in 2.5s, tear down the socket immediately and rotate
  to the next backup IP.

[Action 4: Integrated Worker DoH & DoH-by-IP (Defeating DNS Poisoning)]
- Embed the Worker's own DoH endpoint (https://<worker-domain>/dns-query) into
  Clash, Sing-Box, and v2rayNG subscriptions.
- The Worker resolves DNS queries outside Iran via 8.8.8.8/1.1.1.1 and returns clean
  unpolluted answers.
- Clients querying DoH directly must use IP literals: https://8.8.8.8/dns-query.

[Action 5: Multi-Port Redundancy]
- MCI heavily monitors and QoS-throttles port 443 during peak filtering hours.
- Configure endpoints across Cloudflare's alternate HTTPS ports:
  443, 8443, 2053, 2083, 2087, 2096.

[Action 6: Multi-User Tokenized Architecture]
- Support multiple users where each user has a unique token and UUID.
- Unique subscription URLs: /sub?token=<user_token>.
- Dedicated DoH per user: /dns-query?token=<user_token>.
